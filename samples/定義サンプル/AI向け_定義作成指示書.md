# ヘッダー定義JSON 作成指示書（AI向け）

## 使い方（人間向け）

1. AI（Claude 等）のチャットに、**この指示書の「ここから下をAIに渡す」以降すべて**を貼り付ける。
2. 続けて **IF仕様書の抜粋**（項目一覧の表をテキストにしたもの。Excelからコピーしたタブ区切りでも可）を貼り付ける。
   - 可能なら**実データを数行**添えると、AIが桁数・区切り・パディングを照合できて精度が上がる（個人情報はマスクすること）。
3. AIが出力した JSON を `.json` ファイルに保存してビューアへドラッグ&ドロップ、または ⚙設定 のテキストエリアに貼り付けて登録する。
4. 貼り付けたテキスト（タブ名「貼り付けN」）には `match` が一致しないため、ツールバーの「ヘッダー定義」で**手動で選択**する。
5. 「✔ 検査」「📊 列情報」で実データと突き合わせ、AIの「確認事項」に挙がった点を仕様書と照合して直す。

---

## ここから下をAIに渡す

あなたは、システム間連携IFファイルのビューア（IFファイルビューア）で使う **ヘッダー定義JSON** を作成する担当です。
このあと渡す **IF仕様書の抜粋**（と、あれば実データのサンプル）を読み、以下の仕様に厳密に従って定義JSONを出力してください。

### 1. 出力形式

次の2つだけを、この順番で出力してください。前置きや解説文は不要です。

1. **定義JSON**：```json のコードブロック1つ。トップレベルは**配列**（定義が1つでも配列にする）。
2. **確認事項**：JSONの後に箇条書き。仕様書から読み取れず推測で埋めた点、仕様書内の矛盾（桁数の合計がレコード長と合わない等）、ビューアで表現できず省略した仕様を列挙する。なければ「なし」。

JSONにはコメントを書けません。補足は確認事項に書いてください（どうしてもJSON内に残す場合は `"_memo": "..."` キーを使う。ビューアは無視する）。

### 2. 定義オブジェクトの項目

| 項目 | 必須 | 型 | 内容 |
|---|---|---|---|
| `name` | 推奨 | 文字列 | 定義の表示名。IF名・ファイル名・形式が分かるように（例: `"受注明細IF（固定長・SJIS）"`） |
| `match` | ✔ | 文字列 | ファイル名のワイルドカード（`*`=任意文字列、`?`=任意1文字、大文字小文字無視）。仕様書のファイル名から日付・連番部分を `*` にする（例: `IF_ORDDTL_YYYYMMDD` → `"IF_ORDDTL_*"`）。ファイル名が不明なら IF ID 等から推測し、確認事項に書く |
| `headers` | ✔ | 文字列の二次元配列 | 仮想ヘッダー行。外側=行、内側=列。**1行目=項目名**、**2行目=属性の要約**（例: `"9(8) 必須"` `"X(20)"` `"YYYYMMDD"` `"1=通常/2=返品"`）。各行の要素数は列数と同じにする |
| `delimiter` | — | 文字列 | 区切り文字（`","` `"\t"` `"\|"` 等。複数文字も可）。**固定長のときは書かない** |
| `encoding` | — | 文字列 | 次のいずれかのみ：`shift_jis` / `utf-8` / `utf-16le` / `utf-16be` / `euc-jp` / `windows-1252` / `ascii`。「SJIS」「MS932」「CP932」「Windows-31J」は `shift_jis`。仕様書に記載がなければ書かずに確認事項へ |
| `widths` | — | 正の整数の配列 | **固定長のときだけ**。各項目の**バイト幅**（後述） |
| `details` | — | 文字列の配列 | 列ごとの詳細説明（ヘッダーにマウスを乗せると表示）。仕様書の備考・コード値の意味・桁の詰め方などを書く。改行は `\n`。要素数は列数と同じ（説明のない列は `""`） |
| `rules` | — | オブジェクトの配列 | 検査ルール（後述） |

### 3. 固定長の `widths`

- 値は**バイト数**。`encoding` に応じて計算する：
  - Shift_JIS / EUC-JP：半角（英数・半角カナ）=1バイト、全角=2バイト
  - UTF-8：半角英数=1、日本語=3
  - UTF-16：1文字=2バイト
- COBOL の属性からの換算（Shift_JIS の場合）：`X(n)`=n、`9(n)`=n、`N(n)`（全角）=2n、`S9(n)`（符号付き・ゾーン形式）=n。
  `COMP` / `COMP-3`（パック10進）など**バイナリ項目はテキストとして表示できない**ため、幅だけ合わせて確認事項に書く。
- 仕様書に「開始位置」と「終了位置」があれば、幅 = 終了 − 開始 + 1。開始位置しかなければ、次の項目の開始位置との差。
- **幅の合計をレコード長と照合する**。合わなければ確認事項に書く（FILLER・予備項目の書き漏れが多い。FILLER も1列として含める）。
- 改行コード（CRLF 等）はレコード長に含めない。仕様書のレコード長が改行込みなら、その分を引いて照合する。

### 4. 検査ルール `rules`

1つの列に対して1つのオブジェクト：`{ "col": 列番号, "required": true, "type": "number", "pattern": "..." }`（`col` 以外は省略可）。

- `col`：**1始まり**の列番号。
- `required`：`true` で空欄（スペースのみを含む）をNGにする。仕様書で「必須」「○」「NOT NULL」の項目に付ける。
- `type`：
  - `"number"`：前後の空白を除いた値が `^[+-]?\d+(\.\d+)?$` に一致すること（前ゼロ可、カンマ・全角数字は不可）。数値項目（`9(n)`、金額、数量）に付ける。
  - `"date"`：前後の空白を除いた値が **YYYYMMDD / YYYY-MM-DD / YYYY/MM/DD** の実在日付であること。
    これ以外の形式（YYMMDD、YYYYMM、日時 YYYYMMDDHHMMSS 等）には `type` を付けず `pattern` で表す。
  - 空欄は `type` では判定されない（空欄の扱いは `required` だけで決まる）。
- `pattern`：JavaScript の正規表現。**次の2点に必ず注意する**。
  1. **値の前後の空白を除かずに照合される**。固定長の空白詰めがあるので、前後の空白を許す形で書く。
  2. **空欄の値にも適用される**。任意項目は空欄も許す形で書く。

  よって、次の形を基本とする（BODY に本体の正規表現を入れる）：
  - 必須項目：`"^ *(?:BODY) *$"`
  - 任意項目：`"^ *(?:BODY)? *$"`

  使いどころ：コード値（`1|2|9`）、固定値（`"2"` 固定）、桁数固定の数字（`\d{8}`）、英字＋数字の採番（`[A-Z]\d{7}`）、YYYYMM 等の日付形式。
  JSON の中では `\` を二重にする（`\d` → `"\\d"`）。
- 仕様書から根拠を示せないルールは作らない（推測で厳しくするとNGだらけになる）。

### 5. ビューアで表現できない仕様の扱い

- **レコード区分（ヘッダー/データ/トレーラ）で行ごとにレイアウトが違う**ファイル：1つの定義では表せない。レコード種別ごとに別の定義を作り、`name` に種別を入れ、`match` は同じにする（利用者が手動で切り替える）。データレコードの定義を配列の**先頭**に置く。確認事項にその旨を書く。
- 項目間の相関チェック（「区分=2 のとき金額はマイナス」）、件数・合計値の突合、マスタ存在チェック：ルール化せず `details` に記載する。
- 引用符で囲まれた CSV（`"a,b"`）：ビューアは引用符を解釈せず区切り文字で分割する。確認事項に書く。

### 6. 出力前のセルフチェック

- JSON として正しい（末尾カンマなし、文字列は `"`、`\` は二重）。
- `headers` の各行・`details`・`widths` の要素数が、すべて列数と一致している。
- `rules` の `col` が 1〜列数の範囲にある。
- 固定長なら `widths` の合計がレコード長と一致している（不一致なら確認事項に書いた）。
- `encoding` が許可された値のいずれかである。
- 正規表現は `^` と `$` で囲み、空白詰め・任意項目の形（4章）に従っている。

### 7. 入出力例

**入力（仕様書の抜粋）**

```
受注明細ファイル　ファイル名：IF_ORDDTL_YYYYMMDD.dat
形式：固定長　レコード長：50バイト（改行CRLF含まず）　文字コード：Shift_JIS
No	項目名	属性	桁	開始	必須	備考
1	レコード区分	X	1	1	○	"2"固定
2	受注番号	9	8	2	○
3	受注日	9	8	10	○	YYYYMMDD
4	商品名	N	10	18		全角10文字。右スペース詰め
5	数量	9	5	38	○	前ゼロ詰め
6	単価	9	8	43		未設定時はスペース
```

**出力**

```json
[
  {
    "name": "受注明細IF（固定長・SJIS）",
    "match": "IF_ORDDTL_*",
    "encoding": "shift_jis",
    "widths": [1, 8, 8, 20, 5, 8],
    "headers": [
      ["レコード区分", "受注番号", "受注日", "商品名", "数量", "単価"],
      ["X(1) 必須", "9(8) 必須", "YYYYMMDD 必須", "N(10)", "9(5) 必須", "9(8)"]
    ],
    "details": [
      "レコード区分。\"2\" 固定。",
      "受注番号。数字8桁。",
      "受注日。YYYYMMDD形式。",
      "商品名。全角10文字（20バイト）。右スペース詰め。",

      { "col": 3, "required": true, "type": "date" },

```

**確認事項**

- なし（widths の合計 50 バイトはレコード長と一致）
