# サンプルファイル一覧

動作検証に使用したパターンのサンプル集。まず `ヘッダー定義.json` をビューアにドロップして定義を読み込んでから、各ファイルを開くのがおすすめ。

| ファイル | 内容 | 確認できること |
|---|---|---|
| `ヘッダー定義.json` | 仮想ヘッダー定義3件（受注IF/出荷IF/在庫IF） | 定義JSONのD&D読み込み。ファイル名パターンでの自動適用 |
| `IF_ORDER_20260705` | 受注IF（Shift-JIS・CRLF・カンマ区切り・拡張子なし） | 基本動作。仮想ヘッダー2行の自動適用、半角カナ・全角混在 |
| `IF_ORDER_UTF8BOM_20260706` | 受注IF（UTF-8 BOM付き・CRLF） | BOM判定が定義の`encoding`(shift_jis)より優先されること |
| `IF_ORDER_BULK50K_20260706` | 受注IF 5万行×6列 約1.9MB（Shift-JIS・CRLF） | 大量データの性能。区切り文字変更・表示切替・マーカー件数 |
| `IF_SHIP_TAB_20260706` | 出荷IF（UTF-8・**LF改行**・**タブ区切り**） | 定義からタブ区切りが初期適用。改行コード表示がLFになること |
| `IF_STOCK_EUC_20260706` | 在庫IF（**EUC-JP**・CRLF） | 定義からEUC-JPが初期適用され文字化けしないこと |
| `IF_UTF16LE_20260706.csv` | UTF-16LE BOM付きCSV | UTF-16の自動判定（NULが多くてもテキストと判定）。バイナリモードでのUTF-16デコード位置揃え |
| `任意区切りアットマーク.txt` | `@@` 区切り（UTF-8） | 区切りの「＋任意」欄に `@@` を入力してEnter → チップとして保持されること。項目内カンマが分割されないこと（`@@`のみ有効にする） |
| `複数区切りログ.txt` | 半角スペースとカンマが混在するログ風テキスト | 区切りチップで「空白」と「,」の**2つを同時に有効化**すると列が揃うこと |
| `改行混在.txt` | CRLF+LF+CR混在・末尾改行なし（Shift-JIS） | ステータスバーの改行種別「混在」表示と末尾改行「なし」 |
| `制御コード電文.bin` | SOH+ヘッダ、STX+電文(SJIS)+ETX+CRLF×3、EOT、NULパディング | バイナリモード。制御コード候補（STX/ETX/SOH/EOT/CRLF/NUL）をONにしてのマーク表示。クリックでの対応ハイライト |
| `sample.bin` | PNG風ヘッダ+SJIS/UTF-8混在+NUL/BOM断片 | 初期モードの自動判定（バイナリ）。文字コード切替でのデコード差の確認 |

## 試す手順の例

1. `ヘッダー定義.json` をドロップ → 「定義3件を読み込みました」
2. `IF_ORDER_20260705` をドロップ → ヘッダー2行付きのグリッド表示。「桁揃え」に切替、区切り後間隔を変更
3. `IF_ORDER_BULK50K_20260706` をドロップ → スクロール・検索(`C0499`など)・文字列マーカーの件数表示
4. `制御コード電文.bin` をドロップ → バイナリモードで開く。マーカーパネルの「制御コード候補」から STX/ETX をON。デコード側の「受」をクリックして対応バイトのハイライトを確認
5. `任意区切りアットマーク.txt` をドロップ → 区切りの「＋任意」欄で `@@` を登録（チップ化される）
6. `複数区切りログ.txt` をドロップ → 区切りチップ「,」と「空白」を両方ONにして桁揃え表示に
7. `改行混在.txt` で改行を「LF」に明示指定 → CR がデータ側に残ることをバイナリモードでも確認
